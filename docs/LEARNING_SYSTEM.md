# Learning System

## 1. Learning goal
Help a child move from first exposure to multiplication toward understanding, application, flexible reasoning, and eventually fluency.

The goal is not merely memorizing multiplication facts.

## 2. Core learning principle
A fact is not mastered because the child repeatedly answers `3 × 4 = 12`. The game should test and support understanding across different representations and contexts.

## 3. Learning progression
1. Meet multiplication — understand the `×` symbol and repeated equal groups.
2. Recognize — identify multiplication in visual groups/arrays.
3. Connect representations — move among pictures, repeated addition, expression, and result.
4. Apply — solve simple contextual/NPC problems.
5. Construct — create equal groups/rows that represent a multiplication expression.
6. Calculate independently — solve with reduced visual support.
7. Flexible thinking — missing factors, equivalent factor pairs, mixed representations.
8. Fluency — introduce optional/appropriate speed pressure after understanding is established.
9. Mastery — mix representations, contexts, review, and fluent recall.

## 4. Math-fact progression
Learning progression and multiplication-table progression are separate dimensions.

Default content sequence can favor:
- introductory small facts;
- ×1/×2;
- ×5/×10;
- ×3;
- ×4;
- ×6;
- ×7;
- ×8;
- ×9;
- mixed review.

This should not be presented to the child as a rigid sequence of multiplication tables. Previously learned facts continue to appear through spaced review.

A useful default content mix later in progression is approximately:
- 60% current/new learning;
- 30% previous review;
- 10% gentle preview/challenge.

This is a tuning guideline, not a hard rule.

## 5. Skill dimensions
Track understanding by skill/representation, not only by fact.

Initial dimensions:
- `calculate`
- `recognizeGroups`
- `chooseExpression`
- `applyWordProblem`
- `constructGroups`
- `missingFactor`
- `fluency` (future)

A child may remember a fact while still needing help applying or representing it.

## 6. Adaptive repetition
V1 can use deterministic rules; no AI model is required.

Examples:
- frequently missed facts reappear after intervening activities;
- if calculation is strong but application is weak, increase NPC/context problems;
- if a child struggles, restore visual scaffolding;
- mastered facts remain in spaced review instead of disappearing.

## 7. Error handling
Wrong answers are learning opportunities.

Do not use harsh penalties for beginner learning. Preferred sequence:
1. acknowledge gently;
2. Guide provides visual/repeated-addition support;
3. allow retry;
4. record the attempt for adaptation;
5. revisit the concept later in another representation.

Example support for `3 × 4`:
- show three groups of four;
- reveal `4 + 4 + 4`;
- animate counting `4 → 8 → 12`;
- invite another attempt.

## 8. Timed learning
No countdown during initial learning.

Future speed progression can include:
- combo timer: slow response loses combo but not the encounter;
- per-question timer for established facts/elite challenges;
- whole-session speed challenges.

Timers should target facts the learner already understands. Weak concepts should regain time and/or visual support.

## 9. Extensible math domain
Do not model the learning system as multiplication-specific.

Conceptual operation model:
- V1: `MULTIPLICATION`
- Future: `DIVISION`
- Potential later operations may be added without rewriting activities.

A generic problem should be able to express operation, operands, representation/question type, answer, difficulty, skill target, and scaffolding.

Future division learning may include:
- equal sharing;
- equal grouping;
- calculate;
- word problems;
- missing values;
- construct;
- fluency;
- relationships such as `3 × 4 = 12`, `12 ÷ 3 = 4`, `12 ÷ 4 = 3`.
